## Варіант 8. "Фінанси та бухгалтерія"

Бухгалтер має затвердити кошторис, звернутися до кошторису, сформувати кошторис та звірити кошторис. Для роботи з транзакцією слід провести транзакцію, вивчити транзакцію, перенести транзакцію та завірити транзакцію.



## Етап 1. Предметні аналоги базових об’єктів файлової системи

|UML-роль|Сутність ПрО|Обґрунтування|
|-|-|-|
|Actor|Бухгалтер|Виконує всі дії предметної області над кошторисом і транзакцією.|
|Aggregate|Кошторис|Контейнер, який містить транзакції.Аналог каталогу|
|Part|Транзакція|Окремий елемент обліку всередині кошторису. Аналог файлу|

Тип зв’язку між кошторисом і транзакцією: агрегація.
Транзакція є самостійним обліковим записом: вона фіксується в обліку незалежно від кошторису, може бути віднесена до кошторису, але не втрачає сенсу й не зникає автоматично разом із ним. 



## Етап 2. Семантичні відповідності

Усього 8 дій ПрО (по 4 на Aggregate і Part). Для 6 дій знайдено відповідники серед Bash-команд, для двох (по одній на кожен клас) відповідника немає.

|Операція ПрО|Операція Bash|Bash-команда|Обґрунтування|
|-|-|-|-|
|звернутися до кошторису|перейти у каталог|cd|Звернення до кошторису — це "входження" в контейнер, як перехід у каталог.|
|сформувати кошторис|створити каталог|mkdir|Формування кошторису — створення нового порожнього контейнера.|
|звірити кошторис|переглянути вміст каталогу|ls|Звірка кошторису починається з огляду переліку того, що в ньому міститься.|
|провести транзакцію|створити файл|touch|Проведення транзакції створює в обліку новий запис.|
|вивчити транзакцію|переглянути файл|cat|Вивчення транзакції — ознайомлення з її вмістом.|
|перенести транзакцію|перемістити файл або каталог|mv|Перенесення транзакції — зміна її місця розташування, як переміщення файлу.|
|—|змінити файл|nano|Жодна дія ПрО не означає редагування вмісту транзакції.|
|—|створити копію каталогу|cp -r|Немає дії копіювання кошторису.|
|—|створити копію файлу|cp|Немає дії копіювання транзакції.|
|—|видалити порожній каталог|rmdir|Немає дії видалення порожнього кошторису.|
|—|видалити каталог разом із вмістом|rm -r|Немає дії видалення кошторису з транзакціями.|
|—|видалити файл|rm|Немає дії видалення транзакції.|
|затвердити кошторис|—|—|Затвердження — це надання кошторису офіційного статусу; жодна файлова команда такого змісту не має.|
|завірити транзакцію|—|—|Завірення — засвідчення достовірності транзакції; це юридична дія, а не операція з файлом.|

**Перевірка однозначності.** Кожна операція ПрО зіставлена не більше ніж з однією Bash-командою, і кожна Bash-команда — не більше ніж з однією операцією ПрО.

## Етап 3. UML-діаграма

Діаграму класів реалізовано у файлі Finansy.puml. 

Зв’язки Бухгалтера з Кошторисом і Транзакцією підписано діями ПрО, у примітках вказано відповідні Bash-команди (або "немає"). Між Кошторисом і Транзакцією показано агрегацію. 

## Етап 4. Псевдоніми

У файлі Finansy\_aliases.sh створено псевдоніми для шести дій, що мають відповідники. Для "затвердити кошторис" і "завірити транзакцію" псевдоніми не створюються.

Використання:
```
source Finansy_aliases.sh
sformuvaty Kostorys_Q4     # mkdir
zvernutysya Kostorys_Q4    # cd
provesty tx001.txt         # touch
vyvchyty tx001.txt         # cat
zviryty                    # ls
perenesty tx001.txt ../Kostorys_Q1/   # mv
```
